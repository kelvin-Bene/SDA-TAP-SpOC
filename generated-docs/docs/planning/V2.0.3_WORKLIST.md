## Phase 2 — Final prod defects (~30 min)

**Goal:** Close the last known prod issues. After this, prod Playwright should be 92/92 (or 91 passed + 1 legitimately skipped for missing fixture).

### 2.1 Mobile `/dashboard` horizontal overflow

- **Spec:** `UCT-Benchmark-DMR/combined/frontend/e2e/prod/90-mobile-parity.spec.ts:14`
- **Symptom:** `scrollWidth 394 > innerWidth 375` (19px over viewport on iPhone SE 375px width). Only fails on `/dashboard`; other mobile routes pass.
- **Diagnostic plan:**
  1. Navigate to `/dashboard` in Claude-in-Chrome at 375×667.
  2. Run `document.querySelectorAll('*').forEach(e => { if (e.scrollWidth > 375 || e.offsetLeft + e.offsetWidth > 375) console.log(e.tagName, e.className, e.scrollWidth, e.offsetLeft + e.offsetWidth) })` to find the overflowing element.
  3. Likely suspects: the "Top Rank" stat card text, a chart container without `max-width`, an announcement list item with long text, or a sidebar drawer animation state.
  4. Fix with `overflow-hidden` / `max-w-full` / `break-words` as appropriate.
- **Verification:** re-run the mobile-parity spec; should pass.

### 2.2 Scope the axios `Cache-Control: no-cache` header

- **File:** `UCT-Benchmark-DMR/combined/frontend/src/api/client.ts` (currently sets header globally)
- **Why:** Every authenticated GET now triggers a CORS preflight because `Cache-Control` is a non-simple header. The preflight succeeds (we fixed that in `f817ea8`) but adds ~50-100ms to every API call. Once browsers have had a chance to revalidate their old 410s (a few days), we don't need this header on routine reads.
- **Better approach:** leave the global header OFF; add `Cache-Control: no-cache` only on the specific calls that were historically affected (submission predictions + dataset reference-orbits). Those are the endpoints that previously returned cacheable 410s.
- **Change:** remove the default header in `apiClient.create({...})`, then set it per-request in `useSubmissionPredictions` and `useDatasetReferenceOrbits` via axios config.
- **Verification:** preflight no longer fires on `/api/v1/datasets/`, `/leaderboard/`, `/submissions/`, etc. (check network trace). Fires only on `/predictions` and `/reference-orbits`. The backend `Cache-Control: no-store` response header still fires universally, which is the actual protection against future stuck-cache scenarios.

If this changes later, the flip is a one-line edit at `.github/workflows/e2e.yml:11` — delete `continue-on-error: true`.

### 4.1 Revert nginx proxy to internal Railway URL

- **File:** `UCT-Benchmark-DMR/combined/frontend/nginx.conf.template`
- **Trigger:** `backend.railway.internal` resolving cleanly from a frontend container for ≥ 3 consecutive backend redeploys.
- **Action:** restore the `proxy_pass ${BACKEND_URL}/api/;` and `proxy_pass ${BACKEND_URL}/health;` forms (currently hardcoded to `https://backend-production-4b02.up.railway.app`).
- **Benefit:** saves ~50-100ms per proxied request (internal Docker network vs public TLS round-trip).
- **Caveat:** only the frontend's nginx proxy path uses this — the browser's direct-to-backend axios calls are unaffected either way. Low-urgency optimization.
- **Test procedure:** do it as a single commit, monitor Railway logs for "backend.railway.internal could not be resolved" for 24h, revert if it shows up.
